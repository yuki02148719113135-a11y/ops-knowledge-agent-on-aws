# 手順書: Lambda がスロットリングされてバッチが遅れるとき

対象サービス: batch-worker（夜間バッチ・CSV 取り込み・月次集計）
重要度の目安: 業務開始時刻までに終わらない見込みなら SEV2

## 症状
- CloudWatch の `Throttles` メトリクスが増える
- バッチの終了時刻が通常より大幅に遅れる
- リトライが積み上がり、さらに同時実行数を圧迫する

## 確認すること
1. 対象関数の `Throttles` と `ConcurrentExecutions` のグラフ
2. アカウント全体の同時実行数の上限と、他の関数の使用状況
3. 対象関数に予約同時実行数（Reserved concurrency）が設定されているか

## 対処
1. 同じアカウントの他の関数が同時実行数を使い切っていないか確認し、必要なら一時的に止める
2. バッチ関数に予約同時実行数を設定して、必要な枠を確保する
3. SQS から起動している場合は、最大同時実行数（maximum concurrency）でペースを制御する
4. 遅延が大きい場合は、未処理分だけを再実行する

## 再発防止
- 月次集計など負荷の大きいバッチは、日次バッチと時間帯をずらす
- アカウントの同時実行数の上限緩和を申請しておく
- リトライには指数バックオフを入れる
