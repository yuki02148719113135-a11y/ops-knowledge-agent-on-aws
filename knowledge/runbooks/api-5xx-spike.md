# 手順書: API の 5xx エラー率が急上昇したとき

対象サービス: order-api ほか HTTP API 全般
重要度の目安: 5xx 率 5% 以上が 5 分続いたら SEV2、注文が全件失敗なら SEV1

## 症状
- 監視で「5xx エラー率」アラームが発火する
- 利用者から「注文ボタンを押すとエラーになる」と問い合わせが来る

## 最初の 10 分でやること
1. 直近 1 時間以内にデプロイがあったかを確認する（デプロイ履歴・リリースチャンネル）
2. デプロイがあった場合は、原因調査より先に **前のバージョンへロールバック** する
3. ロードバランサーのターゲットのヘルスチェック状態を確認する
4. アプリケーションログで 5xx の直前に出ているエラーを確認する（タイムアウト / メモリ不足 / 接続エラー）

## 原因ごとの対処
| ログの傾向 | 考えられる原因 | 対処 |
|---|---|---|
| タイムアウトが多い | 外部 API・DB の応答遅延 | 依存先のステータスを確認。外部 API なら一時的にリトライ回数を下げる |
| メモリ不足で再起動 | 新バージョンのメモリ使用量増加 | メモリ割り当てを増やすかロールバック |
| DB 接続エラー | 接続数の上限到達 | 「DB の接続数が枯渇したとき」の手順書へ |

## 復旧の確認
- 5xx 率が 1% 未満に戻り、15 分間安定していること

## 再発防止
- デプロイ後 15 分は 5xx 率を重点監視する
- ロールバック手順を事前に確認し、判断を迷わない（過去にロールバック未実施で長期化した事例あり）
